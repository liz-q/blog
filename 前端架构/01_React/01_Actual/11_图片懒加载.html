图片懒加载

李征2025/8/27大约 6 分钟

react-lazyload 的核心思想是：监听组件是否进入可视区域（viewport），只有在进入或即将进入可视区域时，才去渲染其真实的、耗资源的子组件（如图片、视频、复杂组件等），否则用一个简单的占位元素（如滚动条高度的空白 div）代替。

其原理可以分解为以下几个关键技术点：

1. 核心机制：Intersection Observer (现代、推荐方式)

这是现代浏览器实现懒加载的首选方案，也是 react-lazyload 在高版本浏览器中使用的核心 API。

  • 什么是 Intersection Observer API？
    它提供了一种异步观察目标元素与其祖先元素或顶级文档视口（viewport）交叉状态的方法。简单说，它可以非常高效地告诉你“一个被观察的元素是否进入了可视区域”。

  • 如何工作？

    1. 创建观察器 (Observer)： 库会创建一个 IntersectionObserver 实例。
    2. 指定回调函数： 当被观察的元素进入或离开视口时，这个回调函数会被触发。
    3. 观察目标元素： 库会将包裹懒加载组件的那个占位符 DOM 元素交给观察器去观察。
    4. 触发加载： 当回调函数被触发，并且检测到目标元素的交叉比例（intersectionRatio）超过了设定的阈值（例如，哪怕只有 1px 进入视口），观察器就会判断元素“可见了”。
    5. 渲染内容： 此时，react-lazyload 会设置内部状态（如 visible = true），触发 React 重新渲染，从而用真实的、沉重的子组件替换掉之前的占位符。

  • 优点：

    • 高性能： 异步操作，不阻塞主线程，与传统的滚动事件监听相比，性能开销极小。
    • 精确： 能准确知道元素与视口的交叉状态。
    • 简单： API 易于使用。

2. 降级方案：Scroll Event Listeners (传统、兼容方式)

为了兼容不支持 IntersectionObserver 的老旧浏览器（如 IE），库会降级使用传统的滚动事件监听方案。

  • 如何工作？

    1. 监听滚动事件： 在组件的生命周期（如 componentDidMount）中，在 window 或其可滚动的父容器上添加 scroll 事件监听器。
    2. 节流 (Throttling)： 滚动事件触发非常频繁，直接计算会导致性能问题。因此，库会使用节流函数来限制回调函数执行的频率（例如，每 100ms 最多执行一次计算），而不是每次滚动都计算。
    3. 计算元素位置： 在节流的回调函数中，计算占位符元素的位置（getBoundingClientRect().top）和视口的高度。
    4. 判断是否可见：
      • elementTop - viewportHeight < offset
      • 如果这个条件成立，说明元素已经滚动到了距离视口底部一定偏移量（offset）的范围内（可能是上方或下方），此时就判定元素“即将进入视口”，触发加载。
    5. 清理： 在组件卸载时，移除事件监听器，防止内存泄漏。

  • 缺点：

    • 性能较差： 需要主动计算元素位置，尤其是在需要监听多个父容器滚动时，实现复杂且对性能有影响。
    • 代码更复杂： 需要自己处理节流、多种滚动容器、元素位置计算等。

react-lazyload 会先检测浏览器是否支持 IntersectionObserver，如果支持则使用现代方案，否则自动降级为传统方案。

3. 占位符策略 (Placeholder)

在真实组件加载之前，必须有一个东西来撑开页面布局，防止滚动条跳动。

  • 实现方式： react-lazyload 会默认渲染一个与原组件同样高度的空的 div 作为占位符。
  • 高度来源： 你可以通过 height 属性直接设置一个固定高度，或者库也会尝试从 placeholder 属性传入的 React 元素中获取高度。
  • 作用： 这个占位符确保了滚动条行为的正确性，也是被 IntersectionObserver 或滚动事件监听所观察的实际目标。

4. 提前加载 (Offset)

为了提升用户体验，避免用户看到一片空白，库支持设置一个 offset 参数。

  • 工作原理： 无论用哪种检测方式，都会在元素真正进入视口之前就触发加载。
    • 例如，设置 offset={100}，意味着当组件距离视口底部还有 100px 时，就会开始加载。这样等用户滚动到这 100px 时，内容可能已经加载完毕，看不到 loading 状态。

实现流程总结（以 IntersectionObserver 为例）

  1. 包装组件： 你用 <LazyLoad> 包裹你的复杂组件 <MyHeavyComponent>。
  2. 首次渲染： LazyLoad 组件初始状态 visible 为 false。它渲染一个具有预期高度的空 div 占位符，并将真实组件 null 或一个 loading 状态。
  3. 创建观察器： 组件挂载后（useEffect 或 componentDidMount），创建一个 IntersectionObserver。
  4. 开始观察： 使用 observer.observe() 开始观察步骤 2 中渲染的那个空 div 占位符。
  5. 触发可见： 当用户滚动页面，导致这个空 div 进入视口（考虑 offset），IntersectionObserver 的回调函数被调用。
  6. 渲染真实内容： 回调函数将 LazyLoad 的内部状态 visible 设为 true，导致组件重新渲染。这次重新渲染，占位符被替换为真正的 <MyHeavyComponent>。
  7. 停止观察： 一旦真实内容被渲染，LazyLoad 会调用 observer.unobserve() 停止观察该元素，因为不需要再监听它了。
  8. 卸载清理： 组件卸载时，断开观察器连接。

代码结构简化示意

import React, { useState, useRef, useEffect } from 'react';

const LazyLoad = ({ children, height = 200, offset = 0 }) => {
  const [isVisible, setIsVisible] = useState(false);
  const placeholderRef = useRef();

  useEffect(() => {
    const placeholderEl = placeholderRef.current;

    // 如果已经可见，就不需要再观察了
    if (isVisible || !placeholderEl) return;

    // 现代浏览器：使用 IntersectionObserver
    if ('IntersectionObserver' in window) {
      const observer = new IntersectionObserver(
        ([entry]) => {
          // 当元素进入视口
          if (entry.isIntersecting) {
            setIsVisible(true);
            observer.unobserve(placeholderEl); // 加载后停止观察
          }
        },
        {
          rootMargin: `${offset}px`, // 通过 rootMargin 实现 offset 提前加载
        }
      );

      observer.observe(placeholderEl);

      // 清理函数
      return () => {
        observer.disconnect();
      };
    } else {
      // 降级方案：传统滚动监听（这里省略复杂实现）
      // ... 添加 scroll 监听，使用节流函数，计算位置，判断是否进入视口...
    }
  }, [isVisible, offset]);

  return isVisible ? (
    children // 可见时渲染真实子组件
  ) : (
    <div ref={placeholderRef} style={{ height: `${height}px` }} /> // 不可见时渲染占位符
  );
};

export default LazyLoad;

优点与注意事项

  • 优点：

    • 显著提升性能： 减少初始渲染的 DOM 节点数量和资源请求。
    • 改善用户体验： 加快页面加载速度（特别是首屏）。
    • 节省流量： 对移动端用户友好。

  • 注意事项：

    • SEO： 如果懒加载的内容对SEO至关重要，需要确保搜索引擎爬虫能够看到这些内容（通常现代爬虫可以执行JS，但最好使用SSR或Native懒加载）。
    • 布局偏移 (CLS)： 如果未正确设置占位符高度，真实内容加载时会导致页面布局跳动，影响用户体验和 Core Web Vitals 分数。务必设置准确的 height 或 placeholder。
    • 过度使用： 并非所有内容都需要懒加载，首屏关键内容应优先加载。
