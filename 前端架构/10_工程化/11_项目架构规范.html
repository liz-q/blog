项目架构规范

李征2025/7/22大约 7 分钟

我来到京东时，负责的这个前端项目在代码规范和提交规范上不够完善。代码规范只有 eslint，提交规范缺失。由于我之前开发项目都要求自己规范开发，突然没有这些规范约束后就很不习惯。而且项目规范在团队协作开发中是非常重要的，如果每个人都按自己的习惯开发，代码格式将非常混乱，不利于维护。从长远考虑的话，增加这些规范是必要的，并且越早越好。所以我这样做了，这篇文章是我把我做的记录下来，以便今后参考。

初始化项目

npm create vite@latest

该命令解析原理可以看这里

安装

cd vite-ts-react-01
pnpm install

前端包管理工具

vite-ts-react-01 是初始化的项目，创建的时候选择了 eslint 所以初始规范只有 eslint。vite-ts-react-01 项目代码保持不动，下面增加的所有配置都在
vite-ts-react-02 项目中操作。

增加 prettier

prettier 是一个代码格式化工具，可以帮助开发人员自动格式化代码，使代码风格保持一致。

  1. 安装
pnpm i prettier -D
  1. 增加配置文件

在项目根目录下增加 .prettierrc 文件。

.prettierrc 全部配置字段及解释

{
  // 分号结尾
  "semi": false,
  // 尾随逗号保留
  "trailingComma": "all",
  // 使用单引号
  "singleQuote": true,
  // 打印宽度为120个字符
  "printWidth": 120,
  // Tab宽度为4个空格
  "tabWidth": 4,
  "endOfLine": "auto",
  // 箭头函数参数周围加上括号
  "arrowParens": "always",
  // 大括号与代码在同一行
  "bracketSameLine": true,
  // 大括号内部不加空格
  "bracketSpacing": false,
  // 不使用实验性三元表达式
  "experimentalTernaries": false,
  // JSX属性值使用单引号
  "jsxSingleQuote": true,
  // 保留引号样式
  "quoteProps": "preserve",
  // 不强制单个属性换行
  "singleAttributePerLine": false,
  // HTML空格敏感性为css
  "htmlWhitespaceSensitivity": "css",
  // Vue脚本和样式不缩进
  "vueIndentScriptAndStyle": false,
  // 文本不换行
  "proseWrap": "never",
  // 不插入格式化标记
  "insertPragma": false,
  // 不要求格式化标记
  "requirePragma": false,
  // 使用Tab缩进
  "useTabs": true,
  // 嵌入语言格式自动
  "embeddedLanguageFormatting": "auto"
}

  "trailingComma": "all",

  1. 解决 Prettier 跟 ESlint 冲突

eslint-plugin-prettier 插件会把跟 prettier 冲突的 ESlint 规则给 off 掉，并使用自己的规则。

安装

pnpm i eslint-plugin-prettier -D

在 eslint.config.js 文件中使用

import js from '@eslint/js'
import globals from 'globals'
import reactHooks from 'eslint-plugin-react-hooks'
import reactRefresh from 'eslint-plugin-react-refresh'
import tseslint from 'typescript-eslint'
// 1. 引入
import eslintPluginPrettierRecommended from 'eslint-plugin-prettier/recommended'

export default tseslint.config(
  {ignores: ['dist']},
  {
    extends: [js.configs.recommended, ...tseslint.configs.recommended],
    files: ['**/*.{ts,tsx}'],
    languageOptions: {
      ecmaVersion: 2020,
      globals: globals.browser,
    },
    plugins: {
      'react-hooks': reactHooks,
      'react-refresh': reactRefresh,
    },
    rules: {
      ...reactHooks.configs.recommended.rules,
      'react-refresh/only-export-components': [
        'warn',
        {allowConstantExport: true},
      ],
      // 2. ESLint 会在检查过程中实际运行 Prettier
      'prettier/prettier': 'error'
    },
  },
  // 3. 作为参数传入
  eslintPluginPrettierRecommended
)

增加 stylelint

  1. 安装预处理器

该项目中使用的 scss，所以按照 vite 官网介绍的流程先安装 sass。
但是在实际开发中由于版本原因需要安装 sass-embedded-win32-x64 和 sass-embedded-darwin-arm64，前者支持 window，后者支持 mac

pnpm i sass-embedded-win32-x64 sass-embedded-darwin-arm64 -D
  1. 安装 stylelint
pnpm i stylelint stylelint-scss -D
  1. 安装 stylelint-config-standard-scss

标准的 scss 代码风格

pnpm i stylelint-config-standard-scss -D
  1. 配置

在项目根目录下创建 .stylelintrc.json，内容如下

{
  "extends": [
    "stylelint-config-standard-scss"
  ],
  "customSyntax": "postcss-scss",
  "rules": {
    "selector-class-pattern": null,
    "font-family-no-missing-generic-family-keyword": null
  }
}

解释这句 "customSyntax": "postcss-scss"：

这个配置用于指定 stylelint 在解析样式文件时使用的自定义语法解析器，主要作用是让 stylelint 能够正确解析 scss/sass
语法，而不是将其视为普通 CSS 处理。

因为，stylelint 默认只能解析标准 css，遇到 scss 特有的语法就会报错。它的工作原理是：scss 代码 → postcss-scss 解析 →
stylelint 检查。

所以还要安装一个 postcss-scss

pnpm i postcss-scss -D
  1. 增加属性排序功能

安装 stylelint-order

pnpm i stylelint-order -D

在 .stylelintrc.json 配置文件中启用

{
  "plugins": ["stylelint-order"],
  "extends": [
    "stylelint-config-standard-scss"
  ],
  "customSyntax": "postcss-scss",
  "rules": {
    "selector-class-pattern": null,
    "font-family-no-missing-generic-family-keyword": null,
    "order/properties-order": [] // 这里定义排序规则
  }
}

针对不同类型的 css 属性排序规则示例：

{
  "rules": {
    "order/order": [
      // CSS 自定义属性 (CSS Variables)	--primary-color: red;
      "custom-properties",
      // SCSS/Less 变量	$primary-color: red;
      "dollar-variables",
      // 普通 CSS 属性声明	color: red;
      "declarations",
      // 嵌套规则或选择器	&:hover { color: blue }
      "rules",
      // @开头的规则	@media (min-width: 600px)
      "at-rules"
    ]
  }
}

针对单个属性排序规则示例：

数组形式：

{
  "rules": {
    "order/properties-order": [
      "position",
      "top",
      "display",
      "width",
      "height"
    ]
  }
}

分组形式（推荐）:

{
  "rules": {
    "order/properties-order": [
      {
        "groupName": "布局",
        "properties": ["position", "top", "left", "display", "float"]
      },
      {
        "groupName": "盒模型",
        "properties": ["width", "height", "margin", "padding"]
      }
    ]
  }
}

预设排序方案，可以使用现成的排序方案

pnpm i stylelint-config-recess-order -D
{
  "extends": [
    "stylelint-config-recess-order"
  ]
}

也可以与 Prettier 配合使用

{
  "extends": [
    "stylelint-config-standard-scss",
    "stylelint-config-recess-order",
    "stylelint-prettier/recommended"
  ]
}

增加 husky

husky 是一个为 git 客户端增加 hook 的工具。

  1. 初始化 husky
npx husky-init install // npm
yarn dlx husky-init    // yarn 2+ 
pnpm dlx husky-init    // pnpm
  1. 安装 husky
pnpm i husky -D
  1. 增加命令

在 package.json scripts 下增加 "prepare": "husky install"，npm install 时默认会执行这个脚本

  1. 修改 hooks

修改 .husky/commit-msg 文件内容

#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx --no-install commitlint --edit $1

修改 .husky/pre-commit 文件内容

#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx lint-staged

增加 lint-staged

lint-staged 是这样一个工具，它可以帮我们过滤出 Git 代码暂存区文件(被 git add 的文件)，在提交时不需要检查全部文件，只需要检查暂存区文件即可。

  1. 安装
pnpm i lint-staged -D
  1. 在 package.json 中增加以下命令
  "lint-staged": {
    "*.{ts,tsx}": [
      "eslint -c eslint.config.js --fix",
      "prettier --write --list-different"
    ],
    "*.{css,scss}": [
      "npx stylelint --fix"
    ]
  },

增加 commitlint

用于检测 git 提交的 message 是否符合规范，如果不符合规范则提交失败。

  1. 安装
pnpm i @commitlint/cli @commitlint/config-conventional -D

@commitlint/cli 是 Commitlint 的命令行工具，读取提交消息并根据 @commitlint/config-conventional 规则校验。

  1. 在 .husky/commit-msg 文件中配置，如上就行

  2. 增加配置文件

在跟目录下增加 .commitlintrc.cjs 文件，内容如下

/**
 feat:新增功能
 fix:修复bug
 docs:文档更新
 style: 代码格式修改
 refactor: 重构代码
 test: 测试用例修改
 build: 构建系统或包依赖修改
 ci: CI/CD 配置修改
 chore: 其他杂项修改
 revert: 回滚到上一版本
 perf: 性能优化
 */

module.exports = {

  // 使用 @commitlint/config-conventional规则
  extends: ['@commitlint/config-conventional'],

  // 定义验证规则
  rules: {

    // header最大94字符
    'header-max-length': [0, 'always', 94],

    // subject不能为空
    'subject-empty': [2, 'never'],

    // type的类型必须在指定范围内
    'type-enum': [
      2,
      'always',
      ['build', 'ci', 'chore', 'docs', 'feat', 'feat', 'fix', 'perf', 'refactor', 'revert', 'style', 'test']
    ],

    // type不能为空
    "type-empty": [2, 'never'],

    // type必须小写
    "type-case": [2, "always", 'lowerCase'],

    // scope 不能为空
    "scope-empty": [0, "never"],

    // scope 必须小写
    "scope-case": [2, "always", "lowerCase"],

    // scope 不限制类型
    "scope-enum": [2, "always", []]

  }

};

增加 import 导入排序

  1. 安装
pnpm i eslint-plugin-simple-import-sort -D
  1. 使用

在 eslint.config.js 文件中

import js from '@eslint/js'
import globals from 'globals'
import reactHooks from 'eslint-plugin-react-hooks'
import reactRefresh from 'eslint-plugin-react-refresh'
import tseslint from 'typescript-eslint'
import eslintPluginPrettierRecommended from 'eslint-plugin-prettier/recommended'
// 1. 引入
import simplePluginSort from 'eslint-plugin-simple-import-sort'

export default tseslint.config(
  { ignores: ['dist'] },
  {
    extends: [js.configs.recommended, ...tseslint.configs.recommended],
    files: ['**/*.{ts,tsx}'],
    languageOptions: {
      ecmaVersion: 2020,
      globals: globals.browser,
    },
    plugins: {
      'react-hooks': reactHooks,
      'react-refresh': reactRefresh,
      // 2. 使用插件
      'simple-import-sort': simplePluginSort,
    },
    rules: {
      ...reactHooks.configs.recommended.rules,
      'react-refresh/only-export-components': ['warn', { allowConstantExport: true }],
      'prettier/prettier': 'error',
      // 3. 配置规则
      'simple-import-sort/imports': [
        'error',
        {
          groups: [
            [
              '^react',
              '^@?\\w',
              '^(@|components)(/.*|$)',
              '^\\.\\.(?!/?$)',
              '^\\.\\./?$',
              '^\\./(?=.*/)(?!/?$)',
              '^\\.(?!/?$)',
              '^\\./?$',
              '^.+\\.?(css)$',
              '^\\u0000',
            ],
          ],
        },
      ],
    },
  },
  eslintPluginPrettierRecommended,
)
